- Dedicated non-login account, root-owned binary/read-only snapshot, root-only environment. No credentials committed. Active/running systemd unit, zero restarts, strict system/home protection and no new privileges.
- Tailnet-only listener; no public proxy/all-interface bind. Authenticated stats from Thor returned HTTP 200 and identical data. Running `/proc/PID/exe` and database hashes match the tested/install artifacts.
- Deployed initialization, tools/list, stats/search/live route passed. Missing/wrong bearer, wrong Host, Origin, invalid top, UTF-8 boundaries and oversized fixed/chunked bodies were rejected.
- Offline Python: 30 regression methods and self-check passed. Rust: format, five tests, Clippy with warnings denied and locked release build passed.
- Real-binary offline smoke: transports/EOF/auth/limits, Python token/retrieval parity, provider contracts, whole-request disconnect recovery and four-attempt ceiling passed. Additional checks exercised oversized 2 MiB provider response, oversized 128 KiB request rejected before provider, and four synchronized held rankings/fifth fail-fast rejection plus release.
- Independent narrow source reviews approved parser and smoke changes. These reviews did not independently rerun suites or certify deployment/third-party skill safety. Earlier failed refreshes preserved the old snapshot; earlier bounded-loop escalations remain failures, not retroactive successes.

## Evidence and reproduction

Local evidence: `index-parser8.log`, `parser8-index-manifest.json`, `deployment.json`, four case route JSON files, `eval40.json` and `eval300.json` under the ignored measurements directory. The HTML report is generated by `scripts/rapport.py --dir <evidence-directory>`; optional deployment/evaluation inputs render the verified service data and matching-snapshot recall. Raw databases, binaries, caches and private measurement artifacts are not committed.

To reproduce retrieval, run the existing evaluation harness with `--top 40` and `--top 300` against one consistent snapshot. To test a deployed provider, use `scripts/mcp_smoke.py --url <internal-mcp-url> --live --out <route.json>` with the token in the environment. The smoke's router description differs from the preserved evaluation case; the four-case report uses the latter. See [README](../README.md) for setup and [deployment guide](../deploy/README.md) for configuration and rollback.

[GitHub Actions](https://github.com/King4s/jev-skill-router/actions/workflows/verify.yml) and the PR show the current remote verification result. Local tests alone do not assert remote CI success.
